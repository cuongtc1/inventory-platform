## Goal

One entrance for the frontend: every request passes CORS and a token check, then goes to the service that owns its URL.

## Your decision

Spring Cloud Gateway **WebMVC**, not the reactive WebFlux variant: same security style and error handler as the other services, and Java 21 virtual threads handle waiting requests without reactive code.

## What we did, step by step

### 1. Version
Spring Cloud has its own release train. start.spring.io's data: 2025.1.4 fits Boot >= 4.0.0 and < 4.2.0-M1, 2026.0 is for Boot 4.2 (RC1). So `spring-cloud.version` = 2025.1.4, imported as a BOM.

### 2. Shared library
- `GlobalExceptionHandler` named Hibernate and Spring Data classes, so a service without them couldn't load it. Those handlers moved to `DataExceptionHandler`, registered only when the classes exist, with `@Order(HIGHEST_PRECEDENCE)` because Spring takes the first advice that matches and the catch-all would win.
- `JwtSecurity`: key, `JwtDecoder`, `role` claim, 401/403 answers; the second copy would have been the gateway's. auth-service uses it too.
- `ErrorCode.SERVICE_UNAVAILABLE` (503) for `ResourceAccessException`: another service is down or too slow.

### 3. The gateway
- Routes in `application.yml`, one per service, including the services of later phases (503 until they exist).
- `SecurityConfig`: CORS first (a preflight has no token), then a valid token for everything except login and health.
- Timeouts `spring.http.clients.connect-timeout` / `read-timeout`, virtual threads on.

### 4. Tests
`GatewayIntegrationTest`: a real gateway on a random port, fake services built on the JDK's `HttpServer`, really signed tokens. 13 tests, no Docker.

### 5. Docker and frontend
- Dockerfile, compose entry waiting for healthy auth-service and product-service, `.env.example` values.
- Frontend: `SERVICE_UNAVAILABLE` in `ErrorCode`; 502/503/504 count as a network error even with a JSON body.
- `vite.config.ts` stays on product-service until the frontend can log in (T3.5).

## Problems we hit and how we fixed them

| Problem | Fix |
|---|---|
| Handler couldn't load without Hibernate and Spring Data | The split above |
| Query arrived as `sort=sku%2Casc` instead of `sku,asc` | Same meaning; the test now compares decoded values |

| Spring Tools and an IDE run of product-service held the library jar | You stopped them for the build |

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now |
|---|---|
| Spring Cloud Gateway only reactive | Also `spring-cloud-starter-gateway-server-webmvc` |
| `spring.cloud.gateway.routes` | `spring.cloud.gateway.server.webmvc.routes` |
| Spring Cloud `Hoxton`-style names | `2025.1.x`, a BOM per Boot line |
| Thread per waiting request, or reactive code | `spring.threads.virtual.enabled: true` |
| `RestTemplate` timeouts in code | `spring.http.clients.*` |

## Concepts explained during this task

- **Gateway checks who, services check what:** role rules belong to the service that owns the resource.
- **CORS and preflight:** the browser's `OPTIONS` "may I?" carries no token, so CORS must run before the token check. Only one place may add the header, or the browser rejects the response.
- **`@Order` on advices:** the first `@RestControllerAdvice` with a matching method wins.
- **BOM:** a pom that only sets versions, imported in `dependencyManagement`.
