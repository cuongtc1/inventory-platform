## Goal

The first endpoints of inventory-service: warehouses, so stock has somewhere to be.

## What we did, step by step

### 1. API
`/api/warehouses`: list (search in code or name), get, create, update, delete, the same pattern as suppliers. Default sort `code`.

### 2. Rules
- Code: same format as a SKU (`CommonValidationUtils.CODE_REGEX`), unique ignoring case.
- Trimmed text; an empty address is `null`.
- A warehouse with stock levels can't be deleted: `409 IN_USE`.

### 3. skuCount
The mockup's SKUs column. One grouped query per page, like `productCount`. A native query for now, because the `StockLevel` entity comes with T4.3.

### 4. Tests
`WarehouseServiceTest`, `WarehouseControllerTest`, `WarehouseRepositoryTest`, `WarehouseIntegrationTest`, `MessagesPropertiesTest`; `SecurityRulesTest` now uses the real endpoint. 48 tests.

| Old | Now |
|---|---|

| Multi-line SQL with string concatenation | Text block `"""..."""` |

## Concepts explained during this task

- **`IN ()` on an empty page** is invalid SQL, so the count query is skipped when the page has no rows.
- **Grouped count:** one query for a whole page instead of one per row (the N+1 problem).
