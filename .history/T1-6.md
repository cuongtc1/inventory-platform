## Goal

Every error the service can return, not only the ones our code throws on purpose, must use the convention format (`type`, `title`, `status`, `detail`, `instance`, `code`, `timestamp`). The basic handler came early in T1.3; this task closed the gaps.

## What we did, step by step

### 1. Wrapped up T1.5
Wrote `.history/T1-5.md`, committed it with the `DONE` status (`d384603`), created `feature/T1.6-error-handling`.

### 2. Listed what the T1.3 handler didn't cover
| Case | Before T1.6 |
|---|---|
| Broken or missing JSON body | Spring's default body, no `code` |
| Wrong type in a body field (`"categoryId": "abc"`, unknown enum) | Same |
| Wrong path variable type (`/api/products/abc`) | Same |
| 405, 415, unknown URL and other Spring MVC errors | No `code` / `timestamp` |
| Two requests pass `existsBySku()` at the same moment; MySQL rejects the second insert | **500** |

| Any unexpected exception | Spring's default |

### 3. Checked the library APIs
- Jackson 3 (`jackson-databind-3.1.5`): `tools.jackson.databind.exc.MismatchedInputException` / `InvalidFormatException` (with `getValue()`), path via `JacksonException.getPath()` → `Reference.getPropertyName()` / `getIndex()`. Jackson 3 exceptions are unchecked.
- Hibernate 7.4: `org.hibernate.exception.ConstraintViolationException` has `getKind()` (`UNIQUE`, `FOREIGN_KEY`, ...), `getConstraintName()` and `getErrorCode()` (the MySQL code).

### 4. Extended `GlobalExceptionHandler`
| Method | Result |
|---|---|
| `handleHttpMessageNotReadable` (override) | Field with a wrong-type value → 400 `VALIDATION_FAILED` with `errors: [{field, "has an invalid value 'abc'"}]` (nested paths like `items[0].quantity` supported); broken/missing JSON → 400 `BAD_REQUEST` |
| `handleTypeMismatch` (override) | 400 `BAD_REQUEST`, "Parameter 'id' has an invalid value 'abc'" |
| `handleNoResourceFoundException` (override) | 404 `NOT_FOUND`, "No endpoint GET /api/unknown" instead of "No static resource api/unknown." |
| `handleExceptionInternal` (override) | Adds `type`, `instance`, `code` (HTTP status name, e.g. `METHOD_NOT_ALLOWED`) and `timestamp` to every other Spring MVC error; 5xx get a generic detail and are logged |
| `handleDataIntegrityViolation` (new) | `UNIQUE` → 409 `DUPLICATE` with a message per key (`uk_products_sku`, `uk_categories_name`, `uk_suppliers_name`); `FOREIGN_KEY` with MySQL 1451 (row still referenced) → 409 `IN_USE`; other FK (referenced row missing, 1452) → 404 `NOT_FOUND`; anything else → 500 |
| `handleUnexpected` (new, `@ExceptionHandler(Exception.class)`) | 500 `INTERNAL_ERROR`, "An unexpected error occurred"; stack trace logged at ERROR |

## Problems we hit and how we fixed them

| Problem | Cause | Fix |
|---|---|---|
| `deleteCategoryStillUsedByProduct` got `InvalidDataAccessApiUsageException` (`TransientPropertyValueException`) instead of a MySQL error | In one Hibernate session, Hibernate knew the product pointed to the category and refused the delete itself, so MySQL never saw it | `entityManager.clear()` first, so the product looks like it was saved by another transaction (the real race); then `deleteById` + `flush` reaches MySQL (error 1451) |
| Unknown URL said "No static resource api/unknown." | Spring treats unmatched URLs as missing static files | Override `handleNoResourceFoundException` |
| IDE briefly reported `NoResourceFoundException cannot be resolved` | Import added in the next edit | Nothing to fix |

Expected log output in tests: two `ERROR ... Unexpected error on GET /api/products/1` stack traces from the 500 tests, and MySQL `foreign key constraint fails` warnings from the MySQL test.

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now (Boot 4 / Java 21) |
|---|---|
| `com.fasterxml.jackson.databind.exc.*` (checked, `IOException`) | `tools.jackson.databind.exc.*` (unchecked, `RuntimeException`) |
| `if (x instanceof Foo) { Foo f = (Foo) x; }` | `if (x instanceof Foo f)` (Java 16) |
| `switch` statement with `break` | `switch` expression with `->` that returns a value (Java 14) |
| Unknown URLs went to Boot's `/error` page | Spring 6.1+ throws `NoResourceFoundException`, handled by `ResponseEntityExceptionHandler` as a Problem Details 404 |
| `StringBuilder.length() == 0` | `StringBuilder.isEmpty()` (Java 15) |

## Concepts explained during this task

- **Check-then-act race:** "check SKU is free, then insert" isn't atomic; two requests can both pass the check. The service check gives a precise message in the normal case; the database constraint is the guarantee, and the handler turns its error into the same 409.
- **Foreign key errors in both directions:** deleting a parent that is still referenced (MySQL 1451) is "in use"; inserting a child whose parent is gone (1452) means the referenced record doesn't exist.
- **Don't leak internals:** 500 responses never contain exception messages, SQL or stack traces; those go to the log. The test checks that "connection pool exhausted" doesn't appear in the body.
- **`ResponseEntityExceptionHandler`:** a base class that already turns ~20 Spring MVC exceptions into Problem Details. Overriding single methods customises one case; overriding `handleExceptionInternal` touches all the rest.
- **Hibernate session vs database:** inside one session Hibernate checks some rules itself before sending SQL; to test what the database does, tests sometimes need `clear()` to make Hibernate forget what it knows.
