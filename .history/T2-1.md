## Goal

Turn the T2.0 project into an app with real URLs: every screen of the mockup has a route, Phase 2 pages load lazily, and the README explains the React basics used.

## What we did, step by step

### 1. Checked React Router 8's API
Version 8 is very new, so the installed type definitions were the source, not memory:
- `createBrowserRouter` comes from `react-router`, and `RouterProvider` from `react-router/dom`.
- Route `lazy` accepts an object of async functions per route property: `lazy: { Component: () => import(...) }`.
- The splitting option in Vite 8 is `build.rolldownOptions.output.codeSplitting.groups` (`name`, `test`, `priority`).

### 2. Route table (`App.tsx`)
- **Dashboard, Products (list, new, `:id/edit`), Categories and Suppliers:** lazy-loaded pages.
- **Later-phase screens** (users, warehouses, stock, customers, sales orders, purchase orders, notifications, reports): routes that show `ComingSoonPage` with their phase from `TASKS.md`.
- **Login:** outside `AppLayout`, because it has no sidebar.
- **`*`:** `NotFoundPage`. The root route has `ErrorBoundary: RouteErrorPage` and `HydrateFallback: PageLoading`.

### 3. New building blocks
- `layouts/AppLayout.tsx`: the content area with `<Outlet />`, and a spinner while the next page's code loads (`useNavigation`).
- `components/PageHeader.tsx`: the mockup's title row with actions on the right. It renders `<title>`, which React 19 moves into `<head>` by itself.
- `components/PageLoading.tsx`: a spinner. Ant Design 6 renamed `Spin`'s `tip` to `description`.
- `pages/ComingSoonPage`, `NotFoundPage`, `RouteErrorPage`: the error page recognises a missing page file after a new deploy and offers a reload.
- `pages/dashboard/DashboardPage.tsx`: checks product-service through the proxy with `useState` + `useEffect` + `AbortController`, and links to the catalog pages. Ant Design 6 renamed `Alert`'s `message` to `title`.
- Placeholders for products (list and form with `useParams`), categories and suppliers.
- `api/categories.ts` with `getCategories`.
- New texts: tab title, placeholders, coming soon, 404, error page, dashboard.

### 4. Bundle
- The first build put shared code into files named after a random module (`PageHeader-….js`, 460 kB, really Ant Design).
- Named vendor groups fixed that: `vendor-react` (312 kB), `vendor-antd` (467 kB) and `vendor` (57 kB). Our own code is about 11 kB plus 0.4–2.5 kB per page. The size warning is gone.

### 5. Checking in a real browser
- `curl` can't run JavaScript. Headless Edge's `--dump-dom` printed nothing from Git Bash (Edge is a GUI program on Windows), and `--screenshot` from Bash wrote no files. Started from PowerShell with `Start-Process -Wait`, Edge wrote the screenshots, and Claude looked at them.
- Screens checked: the dashboard (connected through the proxy), `/products`, `/products/7/edit`, `/warehouses`, a 404, `/login`, and the dashboard with product-service stopped.

### 6. Fixes found in the screenshots
| Problem | Cause | Fix |
|---|---|---|
| Links were blue; the mockup's are green | Ant Design takes `colorLink` from `colorInfo` (blue) | `colorLink: colors.primary` in the theme |
| Backend down → "Something went wrong" | The Vite proxy answers **502** text, not "no response" | 502/503/504 without our Problem Details JSON → `NETWORK_ERROR` ("Cannot reach the server"); our own JSON is kept as sent. Checks grew from 26 to 30 |
| Login placeholder without padding | It sits outside `AppLayout` on purpose | Padding around the placeholder until Phase 3 |

### 7. Docs
- `frontend/README.md`: routing table, lazy pages and vendor files, and a **"React basics used here"** section (components, JSX, props, state, effects with cleanup and StrictMode, router hooks) with examples from this code and Java comparisons.
- Conventions section 10, "Routes": lazy pages, `ComingSoonPage`, `PageHeader`, `NotFoundPage`/`RouteErrorPage`, and `useEffect` + `AbortController`.

## New compared to Java 8/11 and Spring Boot 2.x

| Java / Spring | React / TypeScript |
|---|---|
| `@GetMapping("/products/{id}")` + `@PathVariable` | Route `/products/:id/edit` + `useParams()` |
| Sealed interface with records | Union of object types with a `status` field (`Connection` in DashboardPage) |
| Field + manual repaint | `useState`: change it with the setter, React re-renders |
| Code in `@PostConstruct` / a listener | `useEffect` after render, with a cleanup function |
| Lazy-loading a bean (`@Lazy`) | `lazy: { Component: () => import(...) }`: the code is downloaded on first visit |
| `@ExceptionHandler` for a controller | Route `ErrorBoundary` |

## Concepts explained during this task

- **Components, JSX, props, state, effects:** see `frontend/README.md`, "React basics used here".
- **StrictMode runs effects twice in development** (run, cleanup, run) to reveal effects that don't clean up. That's why the dashboard's request is cancelled in the cleanup.
- **Dynamic `import()`** creates a separate file per page; React Router waits for it during navigation, and `useNavigation().state === 'loading'` shows the spinner meanwhile.
- **Vendor chunks** change less often than our code, so browsers keep them cached across our releases.
- **Execution policy:** `RemoteSigned` for the current user allows local scripts (like `npm.ps1`) and requires a signature for downloaded ones. `Undefined` everywhere means Restricted.
