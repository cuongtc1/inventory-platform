## Goal

Put the mockup's frame around every page: dark sidebar menu, white top bar, light content area. It has to work on a phone as well as on a desktop.

## What we did, step by step

### 1. The menu as data (`constants/navigation.ts`)
- `NAVIGATION`: sections (Overview, Catalog, Inventory, Orders, Insights, Admin) with entries (`path`, label from `texts.nav`, Ant Design icon), in the mockup's order.
- `activeNavPath(pathname)`: the longest menu path the URL starts with, so `/products/7/edit` highlights **Products**. The dashboard (`/`) only matches exactly.
- A new screen adds one entry here; the layout code doesn't change. Role rules (Phase 3) will filter this list.

### 2. Layout components (`layouts/`)
- `Logo`: the green "S" tile and "Stockline", linking to the dashboard; tile only when the sidebar is collapsed.
- `SidebarMenu`: Ant Design `Menu` (`theme="dark"`, `mode="inline"`). Section titles when expanded, divider lines when collapsed. Each entry is a `<Link>`; `onNavigate` lets the phone drawer close itself.
- `AppHeader`: sticky white bar with the menu button, notifications bell, avatar with "Guest", and **Log out**.
- `AppLayout`: chooses between the desktop sidebar (`Layout.Sider`, 236 px, collapses to 70 px) and the phone `Drawer`.

### 3. Responsive behaviour
| Width | Menu | Top bar |
|---|---|---|
| ≥ 992 px | Sidebar; the button collapses it to icons, the choice is kept in `localStorage` | Bell, avatar with name, "Log out" |
| < 992 px | No sidebar; ☰ opens the menu as a panel from the left, choosing an entry closes it | Icons only, smaller paddings |

- One breakpoint, `MOBILE_MAX_WIDTH = 991` in `constants/app.ts` (Ant Design's `lg`).
- `hooks/useIsMobile.ts`: `useSyncExternalStore` + `window.matchMedia`.
- `hooks/useStoredState.ts`: `useState` that also saves to `localStorage` (wrapped in try/catch: private windows can refuse storage).

### 4. Theme
- New colours in `theme.ts`: sidebar entry text, hover and selected backgrounds, avatar colours.
- `Menu` component tokens for the dark menu: item colours, group titles, `colorSplit` for the dividers, `collapsedWidth` 70.

### 5. Checking in a real browser
- A small script drove headless Edge through the **Chrome DevTools Protocol** (`--remote-debugging-port`, Node 24's built-in `WebSocket`): set the screen size, open a page, click buttons, take screenshots, read values from the page.
- Checked: desktop expanded and collapsed (70 px, kept after navigation), phone 390 px (no sidebar, drawer opens, choosing Categories navigates and closes it), tablet 768 px (drawer), laptop 1024 px (sidebar), no sideways scrolling.

### 6. Docs
- `frontend/README.md`: "Layout and screen sizes" section and "Custom hooks" in the React basics.
- Conventions section 10: new "Layout and responsive design" rules.

## Problems we hit and how we fixed them

| Problem | Fix |
|---|---|
| `darkDividerColor` is not a Menu token in Ant Design 6 (TS2353) | `colorSplit` |
| Collapsed menu items were 80 px wide inside a 70 px sidebar | Menu token `collapsedWidth: 70` |
| Build size warning came back (vendor-antd 520 kB) after adding icons | Separate `vendor-icons` chunk |
| Avatar colours were written into the component | Moved to `colors` in the theme |
| Bell was a Button inside a Link (two nested clickable elements, bad for keyboard and screen readers) | Button that calls `navigate()` |
| `npm audit`: moderate `minimatch` in ESLint tooling | Dev-only; `--force` would downgrade typescript-eslint, so left alone |

## New compared to Java 8/11 and Spring Boot 2.x

| Java / Spring | React / TypeScript |
|---|---|
| A helper class shared by several classes | A **custom hook** (`useXxx`) shared by several components |
| Observer pattern / listener on an external source | `useSyncExternalStore(subscribe, getSnapshot)` |
| Thymeleaf layout / Tiles template | Layout route component with `<Outlet />` |
| Menu built from a config list | `NAVIGATION` array mapped to `Menu` items |

## Concepts explained during this task

- **Custom hooks:** functions starting with `use` that call other hooks; they share logic, not markup.
- **Why `useSyncExternalStore` and not `useEffect` for the screen width:** the first render already has the right value, so a phone never flashes the desktop layout.
- **Responsive design:** one breakpoint from Ant Design's grid; components ask `useIsMobile()` or use Ant Design's responsive props instead of new media queries.
- **Empty space on wide screens (your question):** the content was capped at 1280 px like the mockup. You chose to use the full width (option A); that change is done in T2.3.
