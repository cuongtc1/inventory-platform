## Goal

The main resource of product-service. Same layered pattern as categories and suppliers, plus a list endpoint with several optional filters in any combination. That needs a query built at runtime, which is what JPA Specifications are for.

### 4. Repository and Specifications
- `ProductRepository` now also extends `JpaSpecificationExecutor<Product>`. `findAll(Specification, Pageable)` is redeclared with `@EntityGraph(attributePaths = {"category", "supplier"})` so the page loads both relations in one query. Added `existsBySku`, `existsBySkuAndIdNot`.
- `ProductSpecifications.matching(search, categoryId, supplierId, status)`: one small `Specification` per filter, only for the filters that were sent, combined with `Specification.allOf(list)`. Search is `LOWER(name) LIKE %x% OR LOWER(sku) LIKE %x%`, with `\`, `%` and `_` escaped.

### 5. Service and controller
- `ProductService`: unique SKU (409), category must exist (404), supplier optional but must exist when given (404), name trimmed, prices set to 2 decimals (`money()`), update flushes before mapping. Delete is a hard delete (comment: prefer `INACTIVE` once stock and orders exist).
- `ProductController` at `/api/products`: list with `@ParameterObject ProductFilter` and `@PageableDefault(size = 20, sort = "name")`; get, create (201 + `Location`), update, delete (204).
- `GlobalExceptionHandler`: a query parameter that can't be converted (e.g. `?status=WRONG`) now gives `"has an invalid value 'WRONG'"` instead of the long Java conversion message.

## Problems we hit and how we fixed them

| Problem | Cause | Fix |
|---|---|---|
| `verify(productRepository, never()).delete(any())` didn't compile ("ambiguous") | Spring Data 4 added `delete(PredicateSpecification)` to `JpaSpecificationExecutor`, so `any()` fits two overloads | `any(Product.class)` |
| Unchecked warning on `any(Specification.class)` | Raw type | `ArgumentMatchers.<Specification<Product>>any()` |
| Compile error in `ProductSpecifications` ("unclosed character literal") | Claude wrote the file through a bash heredoc that dropped single backslashes (`'\\'` became `'\'`) | Fixed with the Edit tool; checked the other heredoc files had no backslashes; wrote the rest with the Write tool |
| PUT response showed `"costPrice": 40`, a later GET `40.00` | The response echoed the request's `BigDecimal` scale; the column is `DECIMAL(12,2)` | `setScale(2, RoundingMode.UNNECESSARY)` in the service; the unit test checks scale with `isEqualTo` |
| `cd services/product-service` failed between commands | The shell's working directory had moved | Used absolute paths |

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now (Boot 4 / Java 21) |
|---|---|
| `Specification.where(null).and(...)` | `Specification.allOf(list)` / `Specification.unrestricted()` (Spring Data JPA 4) |
| `JpaSpecificationExecutor` had only `findAll`/`count`/... | Also `delete(PredicateSpecification)` and `PredicateSpecification`, a simpler spec without `CriteriaQuery` |
| Query parameters bound to a JavaBean with setters | Bound to a `record` through its constructor, no annotation |
| `javax.validation.constraints.Digits` etc. | `jakarta.validation.constraints.*` |

## Concepts explained during this task

- **Specification:** one WHERE condition as a Java object (`(root, query, cb) -> cb.equal(root.get("status"), status)`). Small ones are combined with AND/OR, so a list with optional filters needs no `if` jungle of JPQL strings and no method per combination.
- **Entity graph on a redeclared method:** redeclaring `findAll(Specification, Pageable)` in the interface only to add `@EntityGraph` changes how relations are fetched without writing a query. The count query for paging is unaffected.
- **LIKE escaping:** `%` and `_` are wildcards; without escaping, searching `0%` matches every SKU containing `0`.
- **`BigDecimal` scale:** `40` and `40.00` are equal by `compareTo` but not by `equals`, and print differently in JSON. `setScale(2, UNNECESSARY)` throws instead of rounding, which is safe because validation already allows only 2 decimals.
- **Sorting by a related field:** Spring Data accepts property paths in `sort`, e.g. `category.name`, which becomes a join.
- **Separate formatting commits:** a pure whitespace commit can be checked with `git diff --ignore-all-space` (empty) and skipped when reading history (`git blame -w`).
