## Concepts explained during this task

- **Why `Instant` + business zone:** an `Instant` is a point on the UTC timeline. Only when a person picks a *date* ("orders on 22 October") does the zone matter: that day is `[2026-10-21T17:00Z, 2026-10-22T17:00Z)`. Half-open ranges avoid "23:59:59.999" tricks.
- **Money:** calculate at full precision, round once at the end (`HALF_UP`); `isEqualTo` checks scale, `isEqualByComparingTo` doesn't.
- **Auto-configuration:** a library can't rely on component scanning (services scan only their own package), so Spring Boot reads the `.imports` files from every jar. `@ConditionalOnClass` / `@ConditionalOnWebApplication` switch parts off; `@ConditionalOnMissingBean` lets a service replace a bean. This is how Spring Boot's own starters work.
- **`<optional>` dependencies:** the library compiles against web/JPA, but a service only gets them if it adds them itself (the gateway won't).
- **SNAPSHOT versions:** "still changing"; Maven uses the newly installed jar with the same version.
- **Q: Why `libs/` and not `services/`?** Services run (main class, port, schema, Dockerfile, image); a library doesn't and ships inside each service's jar. Separate folders keep build scripts and compose ("for each service: build image") simple, make the build order obvious (libs first), and make the dependency direction visible (services → libs, never the reverse or service → service). Maven itself doesn't care; it's a layout convention (`apps/` + `libs/` in many monorepos).
- **Subagents:** each starts without the conversation and re-reads the rules, so tasks cost more time and tokens, in exchange for a second pair of eyes. History files stay with the tech lead because they depend on the conversation.
