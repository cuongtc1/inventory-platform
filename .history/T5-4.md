## Goal

Make every status change of an order go through one rule check and leave a row in its history.

## Your decisions

| Question | Choice |
|---|---|
| Which actions now, given T6.6 plans pay, ship and cancel with their stock effects | All actions now as plain status changes; T6.6 adds the stock effects |
| How an order reaches COMPLETED | A "Mark as completed" action (`/complete`) |
| Who changes status | STAFF pay, ship and complete; cancel takes MANAGER |

## What we did, step by step

### 1. The rules
`OrderStatus.nextStatuses()`: a `switch` expression over every status, plus `canChangeTo` and `isFinal`. COMPLETED, REJECTED and CANCELLED are final; CANCELLED only from PENDING, RESERVED and PAID.

### 2. One way to change a status
`SalesOrder.changeStatus(next)` asks the enum, throws `InvalidStatusTransitionException` (409) and returns the old status. `OrderStatusService.changeStatus(id, next, note)` is its only caller: the change and the history row in one transaction, then `flush()` so a `@Version` conflict fails as 409 CONCURRENT_UPDATE.

### 3. The API
`POST /api/sales-orders/{id}/pay`, `/ship`, `/complete`, `/cancel` (no body, the whole order back) and `GET /api/sales-orders/{id}/history`. Role rules in `WebSecurityConfig`.

### 4. Library
`InvalidStatusTransitionException` for the existing `ErrorCode.INVALID_STATUS_TRANSITION`; purchase orders use it in Phase 7.

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now |
|---|---|
| `switch` statement with `break` | `switch` expression (`case PENDING -> Set.of(...)`): returns a value, no fall-through, and over an enum it must cover every value |
| One test per value | `@ParameterizedTest @EnumSource(OrderStatus.class)` |

## Concepts explained during this task

- **State machine:** the allowed changes are data (a table) in one place, not `if`s scattered over the services.
- **A lost update:** two people read version 0; without `@Version` the second save silently overwrites the first. With it, the second `UPDATE ... WHERE version = 0` finds no row and fails.
- **Rules belong in the entity:** `SalesOrder` has no status setter, so no code can skip the check.
