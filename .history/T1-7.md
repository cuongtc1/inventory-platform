## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now |
|---|---|
| Validation texts only in `ValidationMessages.properties` | Boot passes its `MessageSource` to the validator: one `messages.properties` for API and validation texts (since Boot 2.6) |
| Custom error text per exception class | `problemDetail.<exception class>` keys override Spring MVC's Problem Details texts (Spring 6) |
| `@SpringBootTest` with a random port + `TestRestTemplate` for integration tests | `@SpringBootTest` + `@AutoConfigureMockMvc`: same full app, faster, no port |

## Concepts explained during this task

- **MessageSource and MessageFormat:** `{0}` placeholders; `''` for an apostrophe only when a message has placeholders (Spring skips MessageFormat for messages without arguments); Bean Validation uses named placeholders like `{min}`.
- **Keys in exceptions, texts at the edge:** the service layer stays language-free; the handler picks the request's language.
- **Test pyramid in this project:** many fast unit tests, slice tests per layer, a few integration tests that run everything together.
- **Tests that can fail:** a guard test is only useful if breaking the guarded thing makes it red, so it was broken once on purpose.
