## What we did, step by step

### 1. Shared pieces
`types/warehouse.ts`, `types/stock.ts`, `api/warehouses.ts`, `api/stock.ts`, `getProductOptions`, `constants/movementType.ts`, texts, routes.

### 2. Pages
- **Warehouses:** list and form, built like Suppliers. MANAGER only.
- **Stock Levels:** search, warehouse filter, Level bar. Managers get Adjust Stock and an Adjust button per row.
- **Adjust Stock:** `/stock-levels/adjust`, with `?productId=&warehouseId=` when opened from a row. Not a `RecordFormPage`: there is no record to load, each save adds a movement.
- **Stock Movements:** search, warehouse, type, date range; signed quantities.
- **Low-Stock Alerts:** the stock list with `lowStock=true` always on.

### 3. New shared components
`WarehouseFilter`, `DateRangeFilter`, `ProductCell`, `StockLevelBar`.

### 4. Removing copies
`toId` moved to `utils/table.ts`, `emptyToNull` to `utils/format.ts`, and the filter width became `useFilterWidth()`. Products, Suppliers and Users now use them.

### 5. Date helpers
`toApiDate` now takes the picker's dayjs value and keeps the calendar day. The old version went through a `Date` and would have given the wrong day for a viewer in a time zone ahead of Vietnam. Nothing used it yet.

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now |
|---|---|
| `DecimalFormat` for a signed number | `Intl.NumberFormat` with `signDisplay: 'exceptZero'`, built into the browser |
| `Date` / `SimpleDateFormat` | dayjs only for picker values; `Intl.DateTimeFormat` to show moments |

## Concepts explained during this task

- **A chosen date has no time zone:** "22/10/2026" is a calendar day, so converting it through a moment can shift it. Only moments need a zone.
- **Hide in the UI, enforce in the backend:** STAFF doesn't see Adjust, and the backend refuses it anyway.
- **A page without side scroll can still be broken:** a popup outside the screen doesn't widen the page, so the check has to look at the popup's own box.
