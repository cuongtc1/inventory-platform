## Goal

The first real REST API in Stockline, built with the full layered structure that every later CRUD task copies: controller → service → repository, with DTOs, a mapper, business-rule exceptions, a global error handler and tests on each layer.

## What we did, step by step

### 1. Wrapped up T1.2
Wrote `.history/T1-2.md` and committed it with the `DONE` status (`e4d4884`), then created `feature/T1.3-category-crud` from the T1.2 branch (T1.2 wasn't merged into `main` yet).

### 2. Checked Boot 4 / Spring Data 4 package names
Before writing tests, looked inside the jars in `~/.m2` to find where classes live now: `WebMvcTest` is in `org.springframework.boot.webmvc.test.autoconfigure`, and the `spring.data.web.pageable.*` properties are in `spring-boot-data-commons`. While writing the error handler, the IDE couldn't resolve `org.springframework.data.mapping.PropertyReferenceException`; the jar showed it moved to `org.springframework.data.core`.

### 3. DTOs, mapper and shared page format
- `CategoryRequest(name, parentId)`: a `record` with `@NotBlank @Size(max = 100)` on `name` and `@Positive` on `parentId`. Same body for create and update.
- `CategoryResponse(id, name, parentId, parentName, createdAt, updatedAt)`.
- `PageResponse<T>(content, page, size, totalElements, totalPages)` with `from(Page)`: the list format from the conventions, used by every list endpoint from now on.
- `CategoryMapper` (`@Component`): entity → response. It reads the lazy `parent`, so it is called inside the service's transaction.

### 4. Repository queries
`CategoryRepository` got derived queries (Spring Data builds the SQL from the method name):
- `findByNameContainingIgnoreCase(text, pageable)` with `@EntityGraph(attributePaths = "parent")`, so each page loads the parents in the same query (no N+1). An empty text matches everything, so one method serves both "list all" and "search".
- `existsByName`, `existsByNameAndIdNot` (for updates: "another row has this name"), `existsByParentId`.

`ProductRepository` got `existsByCategoryId` for the delete check.

### 5. Service rules (`CategoryService`)
- `@Transactional(readOnly = true)` on the class, `@Transactional` on methods that write.
- Names are trimmed and must be unique. MySQL's default collation ignores case, so `cables` and `Cables` count as the same.
- The parent must exist (404 otherwise).
- No loops: walk up from the new parent to the top; meeting the category itself means it would become its own ancestor → 400.
- Update changes the managed entity without calling `save()`; `flush()` runs the UPDATE early so `@PreUpdate` sets `updatedAt` before the response is built.
- Delete is refused with 409 `IN_USE` if the category has subcategories or products.

### 6. Exceptions and the global error handler
- `ApiException` (abstract, holds the HTTP status and `code`) with subclasses `ResourceNotFoundException` (404 `NOT_FOUND`), `DuplicateResourceException` (409 `DUPLICATE`), `ResourceInUseException` (409 `IN_USE`), `InvalidRequestException` (400 `BAD_REQUEST`).
- `GlobalExceptionHandler extends ResponseEntityExceptionHandler`, building `ProblemDetail` with `type`, `instance`, `code` and `timestamp`:
  - one handler for every `ApiException`;
  - `MethodArgumentNotValidException` → 400 `VALIDATION_FAILED` with `errors: [{field, message}]`;
  - `PropertyReferenceException` (unknown sort field) → 400 `BAD_REQUEST`.
- This was planned for T1.6, but the API can't return correct 404/409 responses without it. T1.6 still covers unreadable JSON, wrong parameter types, 500, duplicate SKU and races on unique keys.

### 7. Controller
`CategoryController` at `/api/categories`: list (`search`, `page`, `size`, `sort`; default `name,asc`, size 20), get, create (`201` + `Location: /api/categories/{id}`), update, delete (`204`). `@Tag` and `@Operation` give Swagger readable names; `@ParameterObject` shows page/size/sort as separate Swagger fields. `spring.data.web.pageable.max-page-size: 100` in `application.yml`.

## Problems we hit and how we fixed them

| Problem | Cause | Fix |
|---|---|---|
| Default page size was 10, not 20 (caught by `CategoryControllerTest`) | `@PageableDefault` has its own `size = 10`, which overrides the global default | `@PageableDefault(size = 20, sort = "name")` |
| `PropertyReferenceException` couldn't be imported | Moved in Spring Data 4 | `org.springframework.data.core.PropertyReferenceException` |
| `createdAt` in the POST response (`...450923800Z`) differed from a later GET (`...450924Z`) | Java's clock on Windows has 100 ns precision; `DATETIME(6)` stores microseconds and MySQL **rounds** the rest | `BaseEntity` truncates to `ChronoUnit.MICROS` |
| `"type": "about:blank"` missing from error JSON (found in the end-to-end check) | Spring 7 leaves `type` out while it has its default value | Handler sets `problem.setType(URI.create("about:blank"))`; the controller test checks it |
| Background `spring-boot:run` showed "failed" | The process was stopped on purpose after the checks | Nothing to fix |

Harmless: the IDE briefly reported `ChronoUnit cannot be resolved` between two edits (the import came in the second edit), and the hint "Non type-safe property reference" on `Sort.by("name")` in the test.

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now (Boot 4 / Java 21) |
|---|---|
| DTO classes with getters, `equals`, `hashCode`, `toString` | `record` (Java 16): immutable, one line per field; works with Jackson and Bean Validation |
| Custom error classes, or Boot's `/error` JSON | `ProblemDetail` (Spring 6, RFC 9457) and `application/problem+json` |
| `org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest` | `org.springframework.boot.webmvc.test.autoconfigure.WebMvcTest` |
| `@MockBean` | `@MockitoBean` (`org.springframework.test.context.bean.override.mockito`) |
| `org.springframework.data.mapping.PropertyReferenceException` | `org.springframework.data.core.PropertyReferenceException` |
| JSON strings in tests with `\"` escapes | Text blocks `"""..."""` (Java 15) |
| `list.get(0)` | `list.getFirst()` (Java 21, sequenced collections) |
| `.collect(Collectors.toList())` | `.toList()` (Java 16) |
| Jackson 2 needed `jackson-datatype-jsr310` and a setting to write dates as text | Jackson 3 writes `Instant` as ISO-8601 text by default |

## Concepts explained during this task

- **Layers:** the controller only maps HTTP to Java (no rules); the service holds the rules and the transaction; the repository talks to the database. Entities never leave the service: the mapper turns them into response records.
- **Derived queries:** Spring Data reads the method name (`existsByNameAndIdNot`) and writes the SQL. `existsByParentId` follows `parent.id` through the relation.
- **`@EntityGraph`:** loads a lazy relation in the same query. Without it, listing 20 categories would run 1 query for the page plus up to 20 for the parents (the "N+1 problem").
- **Dirty checking:** an entity loaded in a transaction is "managed"; changing its fields is enough, and JPA writes the UPDATE at commit (or at `flush()`).
- **`@Transactional(readOnly = true)`:** read methods skip dirty checking and tell the database the transaction only reads.
- **Problem Details:** a standard JSON error shape (`type`, `title`, `status`, `detail`, `instance`) plus our own `code`, `timestamp` and `errors`.
- **Test layers:** Mockito tests check rules fast without Spring; `@WebMvcTest` checks URLs, status codes, JSON and validation without a database; `@DataJpaTest` checks queries on real MySQL.
- **`ReflectionTestUtils.setField`:** sets the private `id` in unit tests, where no database generates it.
