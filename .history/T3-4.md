## Goal

Decide what each role may do, and enforce it in the service that owns the data, not only at the gateway.

## What we did, step by step

### 1. The rules
| Service | STAFF | MANAGER | ADMIN |
|---|---|---|---|
| product-service | Read products, categories, suppliers | Also create, change, delete | Same as MANAGER |
| auth-service | Own account | Same | Also `/api/users` |

STAFF keeps reading categories and suppliers: the product list filters need them, even though the mockup hides those menu items from STAFF (hiding is T3.5).

### 2. Shared library
product-service would have been the third copy, so:
- `UserType` moved from auth-service to `common.constant`.
- `JwtSecurity.roleHierarchy()`: ADMIN implies MANAGER implies STAFF.
- `JwtSecurity.configure(http, resolver)`: stateless, no CSRF, resource server, 401/403 answers. `OPEN_PATHS`: health, docs, `/error`.
- `CommonSecurityAutoConfiguration`: `JwtDecoder` (from `JwtCheckProperties`, `stockline.jwt.*`) and `RoleHierarchy` beans.
- `JwtAuditorAware`: the token's email in `created_by` / `updated_by`, chosen automatically when Spring Security is present.
- auth-service lost `AuditorConfig` and its decoder; the gateway lost `JwtProperties` and its decoder.

### 3. product-service
- `config/WebSecurityConfig`: GET `/api/**` needs STAFF, everything else MANAGER.
- `config/OpenApiConfig`: Authorize button.
- `stockline.jwt.*` in `application.yml`, `JWT_SECRET` in compose.

### 4. Tests
- Existing web tests: `@AutoConfigureMockMvc(addFilters = false)`, since they check URLs and JSON. Their checks didn't change.
- `CatalogSecurityTest`: the rule table with `@ParameterizedTest` + `@CsvSource`, real filters and hierarchy.
- `SecurityIntegrationTest`: really signed tokens on MySQL; audit columns name the user.

## Problems we hit and how we fixed them

| Problem | Fix |
|---|---|
| Library didn't compile: no `jakarta.validation` | Optional `spring-boot-starter-validation` |
| The services kept compiling against the old jar after the library failed | Read the library's error first; install it, then build the services |
| `request(String, String)` doesn't exist | `request(HttpMethod.valueOf(method), path)` |
| Bulk rename left imports out of order | Small script sorted them |
| End-to-end script crashed on DELETE's empty body | Only the script; the 204 succeeded |

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now |
|---|---|
| `RoleHierarchyImpl` + `setHierarchy("ROLE_ADMIN > ROLE_MANAGER")` string | `RoleHierarchyImpl.withDefaultRolePrefix().role("ADMIN").implies("MANAGER")`; a `RoleHierarchy` bean is picked up by `authorizeHttpRequests` |
| Copying an `@Bean` config into each service | Own auto-configuration in the library, also listed for `@WebMvcTest` |
| One test method per case | `@ParameterizedTest` + `@CsvSource` |

## Concepts explained during this task

- **Defence in depth:** the gateway checks who, the service checks what, and the service checks the token again, so a direct call to :8082 gets 401 too.
- **Role hierarchy:** a rule names the lowest role allowed.
- **Consequence:** the frontend's catalog pages stop working until it can log in (T3.5).
