## Goal

Turn auth-service from "hands out tokens" into a service that also checks them: signed-in users manage their own account, and ADMINs manage all users.

## What we did, step by step

### 1. Spring Security as a resource server
- `spring-boot-starter-security-oauth2-resource-server` replaced the two single modules from T3.1 (Boot 4's new starter name).
- `SecurityConfig`: new `JwtDecoder` bean; checks signature (HS256, `JWT_SECRET`), expiry against the `Clock` bean, and `iss`.
- `WebSecurityConfig`: `SecurityFilterChain`, stateless, CSRF off. Open: login, health, API docs, `/error`. `/api/users/**` needs ADMIN. Everything else needs any valid token.
- The `role` claim becomes the authority `ROLE_<role>` (Spring's default would read `scope`).

### 2. 401 and 403 in our error format
- Security filters run before Spring MVC, so `GlobalExceptionHandler` normally never sees those errors. The entry point and access-denied handler pass `UnauthorizedException` / `ForbiddenException` to the `handlerExceptionResolver`, which calls the same handler.
- Library: `ForbiddenException`, texts `common.auth.unauthorized` and `common.auth.forbidden`.

### 3. The user's own account
- `GET /api/auth/me`: from the database, not the token; 401 for a user deactivated after login.
- `PUT /api/auth/password`: needs the current password; the new one has 8 to 72 characters (`PasswordPolicy`).

### 4. User management (`/api/users`, ADMIN)
- List with `search` (email or name), `userType`, `status` (`UserSpecifications`, like `ProductSpecifications`), get, create, update, `POST .../deactivate`, `POST .../activate`.
- `activate` isn't in the task text: without it a deactivated user could never come back. Flagged in the task summary; you marked the task DONE with it.
- Two rules so an ADMIN can't lock themselves out: no deactivating yourself, no removing your own ADMIN role.

### 5. Audit and Swagger
- `AuditorConfig`: an `auditorAware` bean replaces the library's; `created_by` / `updated_by` are the token's email, else `system`.
- `OpenApiConfig`: **Authorize** button in Swagger UI.

### 6. Docs
- auth-service README: who may call what, endpoints, rules, tests, what's new.
- Conventions section 11: how a service checks tokens, role checks on URLs, audit from the token, users are deactivated.

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now |
|---|---|
| `spring-boot-starter-oauth2-resource-server` | `spring-boot-starter-security-oauth2-resource-server` (Boot 4) |
| `extends WebSecurityConfigurerAdapter` | A `SecurityFilterChain` `@Bean` |
| `http.csrf().disable().authorizeRequests().antMatchers(...)` | Lambda style only: `http.csrf(c -> c.disable()).authorizeHttpRequests(a -> a.requestMatchers(...))` |
| Own `OncePerRequestFilter` that parses the header | `oauth2ResourceServer(o -> o.jwt(...))` + a `JwtDecoder` bean |
| `@WithMockUser` | `.with(jwt().jwt(...).authorities(...))` |

## Concepts explained during this task

- **Resource server:** a service that doesn't log anyone in with a form, but accepts requests carrying a token.
- **Stateless and CSRF:** no session cookie means the browser never adds the credential by itself, so CSRF can't happen.
- **Tokens outlive deactivation:** a JWT is checked without the database, so a deactivated user's token works elsewhere until it expires (at most 8 hours).
- **Why URL rules, not `@PreAuthorize`:** the `AccessDeniedException` from a method check would reach `GlobalExceptionHandler`'s catch-all and become a 500.
