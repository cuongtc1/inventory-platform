## Goal

Give product-service its tables and the Java classes that map to them. Flyway creates the tables; Hibernate (`ddl-auto: validate`) checks at startup that every entity matches its table. No endpoints yet; T1.3 onward adds them.

## What we did, step by step

### 1. Read the fields from the mockup
`docs/mockup/app.js` shows the columns and form fields:

| Mockup screen | Fields |
|---|---|
| Categories list | Name, Parent, Products (a count, not a column) |
| Suppliers list | Name, Contact, Email, Phone |
| Product form | SKU, Name, Category, Supplier, Cost price, Sale price, Reorder level, Status |

Decisions:
- Product status is `ACTIVE` / `INACTIVE`. The mockup's "Low" is a stock state; inventory-service will work it out from stock levels.
- Category is required on a product, supplier is optional.
- Category names and supplier names are unique.
- Stock quantities are not stored here; they belong to inventory-service.
- No `version` column on `products`; the conventions require it only on rows edited concurrently, such as stock levels.

### 2. Wrote three Flyway migrations
In `src/main/resources/db/migration/`:

| File | Table | Main columns and constraints |
|---|---|---|
| `V1__create_categories.sql` | `categories` | `name` (`uk_categories_name`), `parent_id` → `categories` (`fk_categories_categories`) |
| `V2__create_suppliers.sql` | `suppliers` | `name` (`uk_suppliers_name`), `contact_name`, `email`, `phone` |
| `V3__create_products.sql` | `products` | `sku` (`uk_products_sku`), `name`, `category_id` → `categories`, `supplier_id` → `suppliers`, `cost_price` / `sale_price` `DECIMAL(12,2)`, `reorder_level INT`, `status VARCHAR(20)` |

Every table has `id BIGINT AUTO_INCREMENT`, `created_at` and `updated_at` as `DATETIME(6)`. Foreign keys stay inside `product_db`. The `.gitkeep` in the migration folder was deleted.

### 3. Wrote the entities
In `com.stockline.product.entity`:
- `BaseEntity` (`@MappedSuperclass`): `id`, `createdAt`, `updatedAt`. `@PrePersist` / `@PreUpdate` set the timestamps, so services never set them by hand.
- `Category` with a `@ManyToOne(fetch = LAZY)` self-reference `parent`.
- `Supplier`.
- `Product` with `@ManyToOne(fetch = LAZY)` to `Category` (required) and `Supplier` (optional), `BigDecimal` prices and `@Enumerated(EnumType.STRING)` status.
- `ProductStatus` enum.

Each entity has a protected no-args constructor for JPA, a public constructor for our code, and plain getters and setters (no Lombok, per conventions).

### 4. Added repositories and a repository test
- `CategoryRepository`, `SupplierRepository`, `ProductRepository`: plain `JpaRepository<Entity, Long>` interfaces. Custom queries come with the CRUD tasks.
- `ProductRepositoryTest` (`@DataJpaTest` + Testcontainers MySQL):
  - `save_validProduct_storesAllColumns`: saves a product with a category, its parent and a supplier, clears the cache, reloads it and checks every field.
  - `save_withoutSupplier_isAllowed`.
  - `save_duplicateSku_throwsDataIntegrityViolationException`: MySQL's unique key rejects the second insert.

### 5. Docs
`services/product-service/README.md`: new "Database" section, new files in the file table, and two rows in the "New compared to Spring Boot 2.x" table.

## Problems we hit and how we fixed them

| Problem | Cause | Fix |
|---|---|---|
| A separate `CREATE INDEX` after `CREATE TABLE` would create a duplicate index | InnoDB needs an index on every foreign key column; if none exists when the FK is created, it adds its own (named after the constraint) | Declare `INDEX idx_...` inside `CREATE TABLE`, so the FK uses it |
| `unique = true` on `Product.sku` but not on the other unique columns | With `ddl-auto: validate` Hibernate ignores it; it only matters when Hibernate generates tables | Removed it; a comment points to `uk_products_sku` in the migration |
| `git commit -F -` with a here-string failed in PowerShell | Windows PowerShell 5.1 doesn't pipe the here-string to `-F -` the way bash does | Used `git commit -m @'...'@` |

Harmless output:
- `Hibernate: insert into ...` lines: `@DataJpaTest` turns on SQL logging.
- `HHH000247: ErrorCode: 1062 ... Duplicate entry 'A02'`: expected, logged by the duplicate-SKU test.
- `LF will be replaced by CRLF`: Git's line-ending conversion on Windows.

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now (Boot 4 / Java 21) |
|---|---|
| `java.util.Date` or `LocalDateTime` in entities | `java.time.Instant`; Hibernate 6+ maps it to a UTC timestamp directly |
| `org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest` | `org.springframework.boot.data.jpa.test.autoconfigure.DataJpaTest` |
| `org.springframework.boot.test.autoconfigure.orm.jpa.TestEntityManager` | `org.springframework.boot.jpa.test.autoconfigure.TestEntityManager` |
| `javax.persistence.*` | `jakarta.persistence.*` (Hibernate 7.4) |

## Concepts explained during this task

- **`@MappedSuperclass`:** a parent class whose fields become columns in each child's table. It is not a table and can't be queried on its own.
- **JPA lifecycle callbacks:** `@PrePersist` runs just before INSERT, `@PreUpdate` just before UPDATE.
- **`FetchType.LAZY` on `@ManyToOne`:** the related row is loaded only when you call its getter. The default for `@ManyToOne` is EAGER, which loads it every time. With `open-in-view: false`, lazy relations must be read inside a transaction, i.e. in the service layer before mapping to a DTO.
- **`EnumType.STRING`:** stores `"ACTIVE"` instead of the enum's position number, so reordering the enum can't corrupt data.
- **`BigDecimal` for money:** `double` can't represent values like 0.1 exactly. Compare with `compareTo` / AssertJ `isEqualByComparingTo`, because `8.0` and `8.00` are not `equals`.
- **`@DataJpaTest`:** starts only the JPA part (entities, repositories, Flyway), not controllers. Each test runs in a transaction that is rolled back afterwards. `entityManager.clear()` forces the next read to come from the database instead of the cache.
- **Q: How do I run one test file?** Docker must be running. From `services/product-service`:
  - `.\mvnw.cmd test -Dtest=ProductRepositoryTest`
  - `.\mvnw.cmd test "-Dtest=ProductRepositoryTest#save_duplicateSku_throwsDataIntegrityViolationException"` (keep the quotes in PowerShell because of `#`)
  - In VS Code, with the Extension Pack for Java: the ▶ icons next to the class and methods, or the Testing panel. Right-click → Debug Test for breakpoints.
  - Experiment: removing the unique key from V3 makes the duplicate-SKU test fail. Undo it afterwards, since committed migrations are never edited.
