### 5. Set up tests with Testcontainers
- `TestcontainersConfiguration.java`: a `@TestConfiguration` with a `@Bean @ServiceConnection MySQLContainer` using `mysql:8.4`, the same image as `infra/`.
- `ProductServiceApplicationTests.java`: `@SpringBootTest` plus `@Import(TestcontainersConfiguration.class)`.
- How it works: on each test run Testcontainers starts a new MySQL on a random port, and `@ServiceConnection` replaces the datasource URL, user and password from `application.yml`. Flyway runs, the app context starts, then the container is deleted. Your real `product_db` is never touched; only Docker Desktop must be running.

## Problems we hit and how we fixed them

| Problem | Cause | Fix |
|---|---|---|
| `java -version` showed 25, `JAVA_HOME` pointed to JDK 14 | Several JDKs installed | You set `JAVA_HOME` to JDK 21. My shell was older, so commands used `export JAVA_HOME=".../jdk-21.0.12.1"` |
| `WARNING: A Java agent has been loaded dynamically` | JDK 21 (JEP 451) warns when a library attaches an agent at runtime; Mockito does this to create mocks. A future JDK will block it | Load Mockito as `-javaagent` at JVM start through Surefire's `argLine` |
| Python not found when querying start.spring.io | Python wasn't installed | Used PowerShell `Invoke-RestMethod`; you have since installed Python 3.13 |

Warnings that are expected and harmless:
- `Could not transfer metadata ... flyway-community-db-support ... 401`: Flyway's pom lists extra repositories that need a login; Maven skips them.
- `No migrations found`: the migration folder is empty until T1.2.
- `SpringDoc ... enabled by default`: a reminder to disable Swagger in production.

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now (Boot 4 / Java 21) |
|---|---|
| `spring-boot-starter-web` | `spring-boot-starter-webmvc` (Boot 4 split into smaller modules) |
| One `spring-boot-starter-test` | One test starter per module: `...-webmvc-test`, `...-data-jpa-test`, `...-flyway-test`, ... |
| `flyway-core` was enough | `spring-boot-starter-flyway` + `flyway-mysql` |
| `javax.persistence`, `javax.validation` | `jakarta.persistence`, `jakarta.validation` |
| `@MockBean` | `@MockitoBean` (`@MockBean` removed in Boot 4) |
| H2 in-memory DB for tests | Testcontainers + `@ServiceConnection` (real MySQL, no URL setup) |
| springdoc 1.x/2.x | springdoc 3.x |
| Mockito attached silently | `-javaagent` in Surefire (JEP 451) |
| Jackson 2 (`com.fasterxml.jackson`) | Jackson 3 (`tools.jackson`); annotations such as `@JsonProperty` keep their old package |

## Concepts explained during this task

- **Actuator:** ready-made endpoints about the running app. `/actuator/health` returns `UP`/`DOWN` with a check per component (`db`, `diskSpace`, ...). Later it's used by Docker health checks; by default only `health` is exposed over HTTP.
- **Flyway:** version control for the database. Numbered SQL files (`V1__create_categories.sql`, ...) run once, in order, and are recorded in `flyway_schema_history` with a checksum. Editing a file that already ran makes startup fail, so changes always go in a new file. That's why Hibernate is set to `validate` and not `update`.
- **Testcontainers:** tests start their own temporary Docker containers (here MySQL), so tests run on the real database engine and never touch shared data.
- **Constructor injection vs `@Autowired` fields** (asked before T1.1, recorded here): field injection still works, but constructor injection with `final` fields gives safer objects, plain-Java unit tests and compile errors instead of `NullPointerException`s. Since Spring 4.3 a single constructor needs no `@Autowired`. Adding a constructor parameter only affects code that calls `new`, which is the service's own unit test; classes that use the service get it from Spring and don't change. A constructor with 10+ parameters is a sign the class should be split.

## How to run it yourself

```bash
cd infra
docker compose up -d
cd ../services/product-service
mvnw.cmd test
mvnw.cmd spring-boot:run
```

Then open http://localhost:8082/actuator/health and http://localhost:8082/swagger-ui.html.
