## Goal

Kafka may deliver a message more than once (after a crash, a rebalance, a retry). Apply each event at most once.

## What we did, step by step

### 1. Library: `ProcessedEvents`
`claim(envelope)` runs `INSERT IGNORE INTO processed_events ...` inside the caller's transaction: 1 row the first time, 0 for an event id the table already has. Refuses to run outside a transaction. Times as UTC `LocalDateTime`. Created by `CommonKafkaAutoConfiguration` in services with Spring Kafka and a `JdbcTemplate`. Log text `system.event.duplicate`.

### 2. inventory-service
`StockReserver.reserve` takes the envelope and claims it first, in each retry attempt's transaction; a replay returns the new `AlreadyProcessed` result, and the listener sends nothing.

### 3. order-service
`V6__create_processed_events.sql`; `StockEventHandler` claims and changes the status in one transaction; `StockEventsListener` keeps the "skip what no longer fits" logic outside it.

### 4. Tests
Library: `ProcessedEventsTest` (fake `JdbcTemplate`), auto-configuration. inventory: `ProcessedEventsMySqlTest` (real `INSERT IGNORE`), two replays in `StockReservationSagaTest` (waiting for the consumer group's committed offset), `StockReserverTest`. order: replay in `OrderSagaTest`, `StockEventsListenerTest` through the real handler, `MigrationsTest`.

## New compared to Java 8/11 and Spring Boot 2.x

| Old | Now |
|---|---|
| `if (exists) ... else insert` | One `INSERT IGNORE` statement whose row count answers the question |
| Adding a case to a result type and hoping every caller handles it | A new record in a `sealed` interface: every `switch` over it fails to compile until it handles the new case |

## Concepts explained during this task

- **At-least-once delivery:** Kafka guarantees a message arrives, not that it arrives once; the consumer makes duplicates harmless.
- **Idempotent consumer:** remember the ids of applied events, in the same transaction as the work.
- **Why a rejected order is the dangerous replay:** the unique key on reservations already stops a double reservation, but nothing stops reserving for an order that was rejected earlier, once new stock has arrived.
- **Committed offset as a progress signal:** a consumer group's committed offset says how far it has handled a partition.
