## Goal

You asked whether Phase 2 needs common files before any page exists. Yes: every page in T2.3/T2.4 needs the same building blocks:
- the API client and error parsing
- date and money formatting
- texts and enum labels
- the mapping between Ant Design tables and the API's paging
- the theme colours

Written first, pages only use them. Written per page, they become the next repo-wide refactor (like tabs in T1.5 and messages in T1.7). The shared files need a real project to compile, so T2.0 also creates the Vite project, and T2.1 keeps routing and the page skeleton.

## New compared to Java 8/11 and Spring Boot 2.x

| Java / Spring | Here |
|---|---|
| Record / DTO class | TypeScript `interface` with the same fields |
| `enum` | Union type `'ACTIVE' \| 'INACTIVE'` (no TS `enum` with `erasableSyntaxOnly`) |
| `messages.properties` | `texts.ts` with `as const`: a typo in a key is a compile error |
| `DateTimeUtils` / `MoneyUtils` | `Intl.DateTimeFormat` (with `timeZone`) / `Intl.NumberFormat` (built into the browser) |
| `@RestControllerAdvice` | An Axios response interceptor turning every error into `ApiError` |
| `Map<ProductStatus, ...>` that must cover every value | `Record<ProductStatus, EnumDisplay>`: a missing status is a compile error |
| Maven `pom.xml` + `mvnw` | `package.json` + `package-lock.json` + npm |

## Concepts explained during this task

- **Dev proxy:** the browser calls `localhost:5173/api/...`, the Vite dev server forwards it to `localhost:8082`. One origin for the browser, so no CORS. `API_PROXY_TARGET` has no `VITE_` prefix on purpose: only `VITE_*` variables reach the browser bundle.
- **`ApiError` as a class:** `instanceof ApiError` works at runtime (interfaces disappear when TypeScript becomes JavaScript).
- **`formatToParts`:** `Intl` output differs slightly between browsers ("22/10/2026, 01:30" vs "22/10/2026 01:30"); assembling the parts gives the same text everywhere.
- **Design tokens:** Ant Design styles every component from a few values (`colorPrimary`, `borderRadius`, ...); one change in `theme.ts` restyles the app.
- **Generic component:** `StatusBadge<T extends string>` checks that the value is a key of its display map, like a Java generic method.

## How to run it yourself

```bash
cd frontend
npm install        # with npm 10+
npm run dev        # http://localhost:5173 (start product-service first for /api)
npm run lint
npm run build
```
